# 스택 · 큐 · 덱 — 보너스 과제 2

> 구현은 [`miniredis/adt.py`](../miniredis/adt.py) 에 있다.

## 한 줄 요약

셋은 전혀 다른 자료구조가 아니라 **"어느 쪽 문으로 넣고 뺄지"만 다른 형제**다.
세 개 모두 이중 연결 리스트 하나로 만들 수 있고, 실제로 그렇게 구현했다.

| | 넣는 곳 | 빼는 곳 | 순서 | 시간복잡도 |
|---|---|---|---|---|
| **스택** Stack | 앞 | 앞 | **LIFO** 나중에 넣은 게 먼저 | 모두 O(1) |
| **큐** Queue | 뒤 | 앞 | **FIFO** 먼저 넣은 게 먼저 | 모두 O(1) |
| **덱** Deque | 앞·뒤 | 앞·뒤 | 둘 다 가능 | 모두 O(1) |

## 왜 이중 연결 리스트로 만들면 전부 O(1) 인가

이중 연결 리스트는 양쪽 끝에 보초(sentinel) 노드를 두고 있어서
`insert_front` · `insert_back` · `remove_front` · `remove_back` 이 전부
**포인터 몇 개만 바꾸는 작업**이다. 리스트가 100만 개여도 시간이 같다.

그래서 스택은 "앞 문만 쓰기", 큐는 "뒤로 넣고 앞으로 빼기", 덱은 "둘 다 열기"로
**규칙만 정해주면** 끝난다. 새 자료구조를 짤 필요가 없다.

> 배열로 큐를 만들면 어떻게 될까? `dequeue` 할 때 맨 앞을 빼고 **뒤를 전부 한 칸씩
> 당겨야** 해서 O(n) 이 된다. 이걸 피하려고 원형 버퍼(circular buffer)를 쓰는데,
> 연결 리스트를 쓰면 그 복잡함이 아예 필요 없다.

## 스택 — LIFO

```
push(1) push(2) push(3)        pop() → 3
  ┌───┐                          맨 마지막에 넣은 것이
  │ 3 │ ← 넣고 빼는 문이 하나     가장 먼저 나온다
  │ 2 │
  │ 1 │
  └───┘
```

**어디에 쓰이나**
- 함수 호출 스택 (그래서 무한 재귀가 "stack overflow")
- 되돌리기(Undo) / 브라우저 뒤로 가기
- 괄호 짝 검사, 수식 계산
- **이 프로젝트에서는** 이진 트리를 재귀로 순회할 때 파이썬이 내부적으로 쓴다

## 큐 — FIFO

```
enqueue →  [1][2][3]  → dequeue
   뒤로 들어와서        앞으로 나간다 (줄 서기와 같다)
```

**어디에 쓰이나**
- 작업 대기열, 프린터 인쇄 대기열
- 너비 우선 탐색(BFS)
- **이 프로젝트에서는 두 곳**
  - `BinaryTree.level_order()` — 레벨 순회가 곧 BFS다
  - `PubSub` 의 구독자 수신함 — 먼저 발행된 메시지를 먼저 읽어야 하므로 큐가 맞다

## 덱 — Double Ended Queue

```
push_front ⇄ [1][2][3] ⇄ push_back
pop_front  ⇄           ⇄ pop_back
```

**어디에 쓰이나**
- 슬라이딩 윈도우 최댓값 같은 알고리즘
- 고정 크기 히스토리 버퍼 (한쪽으로 넣고 반대쪽으로 버린다)
- **이 프로젝트에서는 LRU 가 사실상 덱이다**
  - 앞으로 넣기 = "방금 썼다" 표시 (`move_to_front`)
  - 뒤에서 빼기 = "가장 오래된 것 버리기" (`remove_back`)

## 이 미션과의 연결

`store.py` 의 LRU 추적은 **덱 + 해시맵**의 조합이다.

- 덱만 있으면 → 특정 키가 줄 어디에 있는지 찾느라 O(n)
- 해시맵만 있으면 → 가장 오래된 키를 찾느라 O(n)
- **둘을 합치고 Entry 가 자기 노드를 가리키게 하면 양쪽 다 O(1)**

이것이 `Entry.lru_node` 필드 하나가 존재하는 이유다.
